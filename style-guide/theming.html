Style Guide

Theming & Dark Mode

Aurelius Wealth uses a CSS-native dark/light theme system built on light-dark(), color-scheme, and a hidden checkbox pattern. Dark mode is the default. Understanding how this works is essential before adding any new tokens or theme-aware styles.

How It Works

The theme system has three layers: the color-scheme property tells the browser which palette to use, light-dark() picks the correct value automatically, and a hidden checkbox + :has() selector toggles between modes without JavaScript writing to the DOM.

Step 1 — Default dark mode. :root { color-scheme: dark; } tells the browser to treat all light-dark() calls as "resolve to the dark value". This is set in theme/colours.css before any token definitions.

Step 2 — Light mode override. When the hidden .theme-checkbox is checked, html:has(.theme-checkbox:checked) { color-scheme: light; } switches the resolver. Every light-dark() value in every token immediately resolves to its light variant — no class toggling on individual elements needed.

Step 3 — Tokens resolve automatically. Any token defined with light-dark() works in both modes with no extra code. Example: --bg: light-dark(var(--neutral-1), var(--neutral-10)) resolves to light grey in light mode, dark navy in dark mode.

/* theme/colours.css — the foundation */
:root { color-scheme: dark; }                          /* dark is default */
html:has(.theme-checkbox:checked) { color-scheme: light; } /* light on toggle */

/* Any token using light-dark() just works */
:root {
  --bg:      light-dark(var(--neutral-1), var(--neutral-10));
  --bg-card: light-dark(var(--neutral-0), var(--neutral-8));
  --text-1:  light-dark(var(--neutral-10), var(--neutral-0));
}

The Hidden Checkbox Pattern

The theme toggle uses a visually hidden <input type="checkbox"> with class .theme-checkbox. A visible <label for="theme-checkbox"> styled as a toggle switch triggers it. The :has() selector on the <html> element detects the checked state and switches color-scheme — no JavaScript DOM manipulation required for the theme switch itself.

The checkbox must remain in the DOM at all viewport sizes, even when the visual toggle label is hidden via CSS (display:none below 1100px). The user menu "Appearance" item uses for="theme-checkbox" to link to the same input, so the toggle still works on mobile via the dropdown.

Toggle above controls the entire page theme

<!-- Must be in the DOM at all times — even when visually hidden -->
<div class="theme-switcher">
  <input type="checkbox" role="switch" id="theme-checkbox"
    class="theme-checkbox" aria-label="Colour theme">
  <label class="theme-toggle" for="theme-checkbox" aria-hidden="true">
    <span class="theme-label-dark">Dark</span>
    <span class="theme-label-light">Light</span>
  </label>
</div>

<!-- The user menu Appearance item links to the same input -->
<label class="um-item" for="theme-checkbox">
  <!-- icon -->
  Appearance
  <span class="um-hint theme-hint-dark">Dark</span>
  <span class="um-hint theme-hint-light">Light</span>
</label>

Adding a New Theme-Aware Token

When a component needs a colour that changes between modes, add it to theme/colours.css using light-dark(). Never hard-code a hex value in a component file — always define a token first. This keeps re-theming centralised.

/* 1. Define in theme/colours.css */
:root {
  --my-component-bg: light-dark(rgba(0,0,0,0.04), rgba(255,255,255,0.06));
}

/* 2. Consume in your module CSS */
.my-component {
  background: var(--my-component-bg);
}

Gradient-Safe Tokens (--card-fill)

CSS gradient functions (linear-gradient, conic-gradient) do not resolve light-dark() inside their color stops. This is a browser limitation. To use a theme-aware colour as a gradient stop, you must use a :has() override rather than light-dark() directly.

--card-fill and --card-fill-glass are the established pattern. They mirror --bg-card but are defined without light-dark() wrapper:

/* theme/colours.css — gradient-safe pattern */
:root {
  /* Dark default — no light-dark() wrapper */
  --card-fill:       var(--neutral-8);
  --card-fill-glass: oklch(from var(--seed-neutral) 0.22 calc(c * 0.85) h / 0.60);
}

/* Light mode override via :has() */
html:has(.theme-checkbox:checked) {
  --card-fill: var(--neutral-0);
}

/* Usage — safe in gradient stops */
.my-element {
  background: linear-gradient(135deg, var(--card-fill), transparent);
}

⚠️ Never use light-dark() directly inside linear-gradient() or conic-gradient() — use --card-fill or define a new gradient-safe token following this pattern.

Animated Gradient Border (@property --border-angle)

Card gradient borders use a registered @property to animate the border angle. This requires the @property declaration so the browser knows the type and can interpolate it. Used on the onboarding card and similar premium surfaces.

/* Register the custom property so it's animatable */
@property --border-angle {
  inherits: false;
  initial-value: 0turn;
  syntax: '<angle>';
}

/* Apply with conic-gradient and animate */
.gradient-border-card {
  --border-angle: 0turn;
  animation: border-spin 8s linear infinite;
  background:
    conic-gradient(from var(--border-angle),
      transparent 50%,
      var(--gold) 80%,
      transparent 100%
    )
    border-box;
  border: 1px solid transparent;
}

@keyframes border-spin {
  to { --border-angle: 1turn; }
}

Theme Infrastructure Tokens

These tokens control the theming mechanism itself, not colours.

Token / Selector Value Purpose
:root { color-scheme: dark } dark Sets dark as the default mode for all light-dark() resolution
html:has(.theme-checkbox:checked) color-scheme: light Switches to light mode when the toggle checkbox is checked
--card-fill var(--neutral-8) / var(--neutral-0) Gradient-safe card fill; mirrors --bg-card without light-dark()
--card-fill-glass oklch(…/0.60) Semi-transparent dark version for glassmorphism with backdrop-filter

Do & Don't

Do

Use light-dark() for all theme-aware values:

--my-token: light-dark(#eee, #111);
Don't

Hard-code dark hex values in component files:

.my-component { background: #2A2E35; }

Accessibility Notes

ARIA role="switch" — The hidden checkbox uses role="switch" to communicate its toggle behaviour to screen readers. The checked state (on/off) is announced automatically.

Live region — A visually hidden .theme-live element with aria-live="polite" and aria-atomic="true" announces "Dark mode" or "Light mode" when the toggle fires. Populated by JavaScript in sg-shell.js.

Contrast ratios — All text tokens (--text-1, --text-2, --text-3) pass WCAG AA (4.5:1) on their paired background in both light and dark modes. The --gold-text token is specifically calibrated (≈#A05607 in light, gold in dark) to maintain AA compliance on all surface colours.

prefers-color-scheme — The current system does not yet auto-respond to prefers-color-scheme: light. The product defaults to dark and requires explicit user action. This is a known gap — a future enhancement would sync the default to the OS preference on first load.
