Style Guide

Login

The Aurelius sign-in screen replaces the OutSystems default login page. It is a standalone full-page layout at /login/ — it does not use the main app shell. The page uses a premium split-column design: a dark brand panel on the left and a themed form panel on the right. Both panels collapse to a single form-only column at ≤ 960px.

Live Page

The login page lives at /login/ and operates as a fully standalone HTML file — no app shell, no sidebar. Open it directly to see the full split-layout experience including light/dark toggle and form interactions.

The outer wrapper .login-shell is a two-column CSS grid. The left column holds .login-brand (the dark brand panel); the right column holds .login-form-panel (the scrollable form). At ≤ 960px the brand panel is hidden and the form panel becomes full-width.

Password Show / Hide — .login-pw-toggle

A position: absolute button inside .login-pw-wrap that sits flush to the right edge of the password input. Toggling it flips input.type between "password" and "text", swaps the SVG icon between eye and eye-off, and updates aria-label and aria-pressed to keep screen readers informed.

// Password show / hide
(function () {
  var input = document.getElementById('password');
  var btn   = document.getElementById('pw-toggle');
  var icon  = document.getElementById('pw-icon');
  if (!input || !btn) return;

  btn.addEventListener('click', function () {
    var show = input.type === 'password';
    input.type = show ? 'text' : 'password';
    btn.setAttribute('aria-label',   show ? 'Hide password' : 'Show password');
    btn.setAttribute('aria-pressed', show ? 'true'          : 'false');
    // Eye → Eye-off SVG swap
    icon.innerHTML = show
      ? '<path d="M17.94 17.94A10.07 10.07 0 0 1 12 20c-7 0-11-8-11-8a18.45 18.45 0 0 1 5.06-5.94M9.9 4.24A9.12 9.12 0 0 1 12 4c7 0 11 8 11 8a18.5 18.5 0 0 1-2.16 3.19m-6.72-1.07a3 3 0 1 1-4.24-4.24"/><line x1="1" y1="1" x2="23" y2="23"/>'
      : '<path d="M1 12s4-8 11-8 11 8 11 8-4 8-11 8-11-8-11-8z"/><circle cx="12" cy="12" r="3"/>';
  });
}());

Theme Toggle

The login page uses the same hidden .theme-checkbox pattern as the main app — checking it switches color-scheme to light; unchecked is dark. The login page adds localStorage persistence so the user's preference carries across to the main dashboard after sign-in. The toggle is rendered as a <label> so keyboard focus and click both work without extra JS.

// Theme toggle (login page — persists to localStorage)
(function () {
  var cb    = document.getElementById('theme-checkbox');
  var label = document.getElementById('theme-label');
  if (!cb) return;

  var stored  = localStorage.getItem('aurelius-theme');
  var isLight = stored
    ? stored === 'light'
    : window.matchMedia('(prefers-color-scheme: light)').matches;

  cb.checked        = isLight;
  label.textContent = isLight ? 'Dark mode' : 'Light mode';

  cb.addEventListener('change', function () {
    var light = cb.checked;
    label.textContent = light ? 'Dark mode' : 'Light mode';
    localStorage.setItem('aurelius-theme', light ? 'light' : 'dark');
  });
}());

Accessibility Checklist

Requirements for the login page to meet WCAG 2.1 AA and FCA accessibility guidance.

  • Labelled inputs. Every input has a visible <label> associated via for/id. Required fields carry aria-required="true" and a visual asterisk (aria-hidden="true" so it is not double-announced).
  • Password toggle. Uses aria-label ("Show password" / "Hide password"), aria-pressed, and aria-controls pointing to the input. An .sr-only hint describes the toggle to assistive technology.
  • Focus indicators. All interactive elements have :focus-visible outlines keyed to var(--gold). The outline is never suppressed.
  • Decorative panel. .login-brand carries aria-hidden="true" and role="presentation" so screen readers skip it entirely.
  • Risk warning. Marked with role="note" and a descriptive aria-label so AT users hear it in the document structure.
  • No colour-only information. The asterisk on required fields, the risk icon, and the FCA badge all have text or ARIA equivalents.
  • Keyboard navigation. Tab order: email → password → show/hide → remember → forgot → submit → contact. No focus traps.
