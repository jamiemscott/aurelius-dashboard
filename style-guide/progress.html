Style Guide

Progress & Stats

Horizontal progress bars for allocation/holdings, and stat chips for key metrics. Defined in modules/progress.css. Progress items are used in fund breakdown lists; stat chips appear as summary rows on portfolio and holdings pages.

Progress Items (.progress-item)

Each progress item is a flex row: a coloured dot (.progress-dot), a label (.progress-label), the percentage bar (.progress-bar-wrap containing .progress-bar-track and .progress-bar-fill), and a percentage text (.progress-pct). The fill width is set as an inline style on .progress-bar-fill.

</div>

Stat Chips (.stat-chip)

Compact metric display units arranged in a .stat-row flex container. Each chip has an uppercase tracking label (.stat-chip-label) and a value (.stat-chip-value). Value modifiers: no modifier (default text-1), add .is-gold for gold, .is-green for positive gains, .is-red for losses.

Do & Don't

Do

Always set the fill width as an inline style attribute so OutSystems can drive it from data. Never hardcode the width in a modifier class.

Don't

Don't use more than 5–6 stat chips in a single .stat-row — they become too dense on tablet breakpoints. Split into two rows or use a grid if more are needed.

Accessibility Notes

Progress bars should use role="progressbar", aria-valuenow, aria-valuemin="0", and aria-valuemax="100" on the fill element. This allows screen readers to announce the allocation. Stat chip colour modifiers (green/red) must not be the only way to convey direction — the sign character (+ or −) must always be present in the value text.
