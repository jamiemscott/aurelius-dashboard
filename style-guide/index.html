Style Guide

Colours

All colour decisions flow from three seed values in theme/brand.css. Consuming CSS must always use the semantic token names — never raw hex values. This ensures both light and dark modes resolve automatically.

Brand Tokens

The primary gold palette derived from --seed-primary: #F5A623. Use --gold for primary actions, --gold-text for accessible text on light or dark surfaces, and alpha variants for tinted backgrounds.

--gold
Primary action
--gold-soft
Secondary / soft gold
--gold-text
AA text on surfaces
--gold-dim
Tinted fill / bg
--gold-glow
Hover glow
--brand-300
Scale step 300
--brand-500
Seed (≈ #F5A623)
--brand-700
WCAG-AA on white
/* Use semantic aliases — not scale steps directly */
color: var(--gold-text);          /* AA-safe gold text */
background: var(--gold-dim);      /* tinted gold background */
border-color: var(--gold-glow);   /* subtle gold border/glow */
background: var(--gold);          /* solid gold — buttons only */

Surface Tokens

Three surface layers build depth. --bg is the page canvas, --bg-card lifts panels and cards, --bg-hover and --bg-input are for interactive and form states. All resolve correctly in both light and dark via light-dark().

--bg — Page canvas
--bg-card — Card / panel surface
--bg-hover — Hover state / interactive element
--bg-input — Form input background
--bg-dark — Dark chrome (header, sidebar rail)

Text Tokens

Three text levels create visual hierarchy. All pass WCAG AA (4.5:1) on their paired background. Never use --text-3 for body copy — it is for decorative labels only.

--text-1 Primary — headings, values, strong emphasis

--text-2 Secondary — body copy, descriptions, sub-labels

--text-3 Tertiary — captions, timestamps, decorative labels

Borders & Dividers

--border is for card outlines and interactive element edges. --divider is lighter — for internal row separators and subtle rules. Both are pure black/white alpha, intentionally hue-neutral.

--border — Card edges, input outlines, interactive borders
--divider — Internal rows, section separators

Status Colours

Semantic colours with a fixed meaning that must not change across re-themes. Dark variants are vivid for visibility; light variants pass WCAG AA on white. Always pair the solid token with its -dim variant for backgrounds. New modules should use the --status-* names; --green and --red are legacy aliases kept for backwards compatibility.

--status-success
Success · gain · alias: --green
--status-success-dim
Success background · alias: --green-dim
--status-error
Error · loss · alias: --red
--status-error-dim
Error background · alias: --red-dim
--status-warning
Warning · attention required
--status-warning-dim
Warning background
--status-info
Informational · neutral notice
--status-info-dim
Info background
/* New modules — use --status-* names */
color:      var(--status-success);
background: var(--status-success-dim);

color:      var(--status-error);
background: var(--status-error-dim);

color:      var(--status-warning);
background: var(--status-warning-dim);

color:      var(--status-info);
background: var(--status-info-dim);

/* Legacy aliases (existing modules only) */
color: var(--green);   background: var(--green-dim);
color: var(--red);     background: var(--red-dim);
