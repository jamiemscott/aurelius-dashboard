Style Guide

Layout

The Aurelius shell is a three-region CSS grid: topbar, sidebar, and main. All layout primitives are defined in layout/layout.css. Page-level content uses .page-section as the scroll-safe container, and column layouts (.two-col, .three-col, .two-col-equal) for responsive multi-column composition.

Shell Grid — .shell

The outer layout wrapper. A CSS grid with three named areas: the fixed topbar, fixed sidebar, and scrolling main. The --topbar-h and --sidebar-w tokens define the dimensions. Never add padding or margin to .shell directly — use the inner regions. The modifier .shell--no-sidebar removes the sidebar for full-width pages like onboarding.

header [topbar-h]
aside
[sidebar-w]
main
.main 
<!-- Standard shell -->
<div class="shell">
  <header role="banner"><!-- topbar --></header>
  <aside class="site-sidebar"><!-- sidebar --></aside>
  <main class="main" role="main"><!-- content --></main>
</div>

<!-- Full-width (no sidebar) -->
<div class="shell shell--no-sidebar">
  <header role="banner"><!-- topbar --></header>
  <main class="main" role="main"><!-- full-width content --></main>
</div>

Page Section — .page-section

The standard content wrapper inside .main. Provides consistent horizontal padding and max-width clamping to keep content readable at wide viewports. Every distinct block of page content — a table, a chart, a KPI group — should live inside its own .page-section.

.main
.page-section — page header
.page-section — KPI grid
.page-section — table
.page-section — chart 
<main class="main" role="main">
  <section class="page-section">
    <div class="page-header"><!-- h1 + actions --></div>
  </section>
  <section class="page-section">
    <div class="kpi-grid"><!-- KPI cards --></div>
  </section>
  <section class="page-section">
    <div class="table-wrap"><!-- table --></div>
  </section>
</main>

Two Column — .two-col

An asymmetric two-column grid — main content left (wider), supporting content right (narrower). Collapses to a single column on small viewports. Use for chart + summary, table + filter panel, or chart + allocation breakdown arrangements.

.two-col — primary (wide)
.two-col — secondary (narrow) 
<div class="two-col">
  <div class="card card-pad"><!-- primary: chart, table --></div>
  <div class="card card-pad"><!-- secondary: summary, filters --></div>
</div>

Two Column Equal — .two-col-equal

A symmetric 50/50 two-column grid. Use when both columns have equal visual weight — e.g. two charts side by side, or a card pair. Collapses to single column below the breakpoint.

</div>

Three Column — .three-col

An equal three-column grid for dense comparative content. Each column is ~33% of the available width. Collapses progressively: 3 → 2 → 1 column at smaller viewports. Use sparingly — only when three genuinely parallel items exist (e.g. three allocation category panels).

Centred Column — .main--centred

Add .main--centred alongside .main on any .shell--no-sidebar page where the content should sit in a constrained, readable column rather than stretching edge-to-edge. The modifier uses progressive inline padding — the column is clamped to 960px and auto-centred as the viewport grows. No extra wrapper div is required; the existing .main padding still applies at narrower viewports.

Page Header — Standalone — .page-header--standalone

Use .page-header--standalone alongside .page-header on no-sidebar pages. It adds a bottom border and extra vertical spacing to visually separate the title block from the page body. The header supports an optional .header-actions slot on the right for buttons or controls. For the title use .page-title; for a subtitle or context line use .page-date.

Chat Page Layout — .chat-main / .chat-wrap

Two classes work together to give the AI chat page its viewport-filling layout while keeping the site footer scrollable below. Apply .chat-main alongside .main on the <main> element; wrap chat UI content in .chat-wrap.

.chat-main — replaces the standard .main padding with var(--pad) var(--pad) 0 (no bottom padding — the footer provides its own spacing) and sets overflow-y: auto so the full page is scrollable.

.chat-wrap — the container for the chat interface itself. Uses a clamp() min-height so it fills the visible viewport on first load, then allows the footer to scroll into view below. Constrained to max-width: 760px and centred at ≥ 768px.

<!-- Shell: no sidebar for the chat page -->
<div class="shell shell--no-sidebar">
  <!-- topbar -->

  <main class="main chat-main" role="main">

    <!-- Page header (breadcrumb + title + date + actions) -->
    <div class="page-header page-header--standalone">
      <!-- ... -->
    </div>

    <!-- Chat interface fills the viewport on first load -->
    <div class="chat-wrap">
      <!-- message list, input, etc. -->
    </div>

    <!-- Full site footer — scrollable below the chat on first load -->
    <footer class="site-footer">
      <!-- ... -->
    </footer>

  </main>
</div>

Layout Principles

Rules to follow when composing pages in the Aurelius dashboard.

  • Nesting depth. Never nest column grids inside column grids. .two-col inside .three-col creates unpredictable results. Use .page-section to separate layout regions vertically.
  • Card as layout block. Cards (.card) are the atomic layout unit for column content. Do not place raw content directly inside .two-col — wrap it in a card first.
  • Scroll region. The .main region is the only scrolling region. The topbar and sidebar are position-fixed. Never add overflow scroll to .page-section or column wrappers.
  • Spacing. Use gap: var(--pad) between column children. Vertical spacing between .page-section blocks is handled by the layout CSS — do not add extra margin-bottom to sections.
  • No-sidebar pages. Use .shell--no-sidebar for full-immersion experiences (onboarding, chat) and for utility pages (settings, forms) where the sidebar navigation would be a distraction. Add .main--centred to constrain content to a readable column width on wider screens.
  • Page header on no-sidebar pages. Always pair .page-header--standalone with .page-header on no-sidebar pages. The bottom border provides essential visual separation between the title and the page body that the sidebar's presence normally implies.
