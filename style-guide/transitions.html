Style Guide

Transitions

Cross-document page transitions using the CSS View Transition API. When enabled, navigating between pages animates the main content area while the topbar and sidebar stay visually frozen — giving the product an app-like feel without any JavaScript routing. Defined in modules/transitions.css, compiled into bundle.css.

How It Works

The View Transition API is entirely CSS-driven. @view-transition { navigation: auto } in bundle.css tells the browser to intercept same-origin navigations and run a transition. No JavaScript required.

1. Capture

Browser snapshots the current page before navigation.

2. Navigate

Normal page fetch happens in the background.

3. Render

New page renders off-screen; named elements are paired.

4. Animate

Old and new snapshots cross-animate via ::view-transition-* pseudo-elements.

Both documents must opt in. @view-transition { navigation: auto } must be present in the old page and the new page for the transition to fire. Since it lives in bundle.css, which is included on every page, this is handled automatically.

/* In bundle.css — applies to every page automatically */
@view-transition {
  navigation: auto;
}

Opting In — class="vt-page"

Transitions are gated behind the presence of a .vt-page element in the DOM. Add the class to the shell wrapper (or any element on the page) to enable named region tracking and the slide animation. Pages without the class still navigate normally — they just don't get the animated treatment.

Do — animated page 
<div class="shell vt-page">
  <header role="banner">…</header>
  <aside class="site-sidebar">…</aside>
  <main class="main">…</main>
</div>
Neutral — no transition
<div class="shell">
  <header role="banner">…</header>
  <aside class="site-sidebar">…</aside>
  <main class="main">…</main>
</div>

OutSystems note. OS doesn't allow custom classes on <html>. Use :has(.vt-page) — the selector in transitions.css matches any document whose DOM contains a .vt-page element, so placing it on the outermost available div is sufficient.

/* Named regions are only assigned when .vt-page exists in the DOM */
body:has(.vt-page) [role="banner"] { view-transition-name: vt-topbar;  }
body:has(.vt-page) .site-sidebar,
body:has(.vt-page) .sidebar        { view-transition-name: vt-sidebar; }

Named Regions

A view-transition-name assigns an element to a named snapshot slot. Elements with the same name on both pages are treated as the same persistent surface — the browser composites them as frozen chrome. Elements with a name on only one page animate in or out. The root pseudo-element captures everything not claimed by a named element.

topbar vt-topbar · frozen ❄
sidebar vt-sidebar · frozen ❄
main (root) root · slides in ↑ not named — part of root snapshot

Why .main has no name. Chrome's UA sheet sets overflow: clip on named element image pairs, which silently clips the translateY slide animation. Leaving .main unnamed means it falls into the root snapshot, where our keyframes run without any clipping.

/* Static chrome — named but no keyframes → visually frozen */
body:has(.vt-page) [role="banner"] { view-transition-name: vt-topbar;  }
body:has(.vt-page) .site-sidebar,
body:has(.vt-page) .sidebar        { view-transition-name: vt-sidebar; }

/* Suppress the browser's default crossfade on frozen surfaces */
::view-transition-old(vt-topbar),
::view-transition-new(vt-topbar),
::view-transition-old(vt-sidebar),
::view-transition-new(vt-sidebar) {
  animation: none;
}

/* .main is intentionally NOT named — animates via root instead */

Animation — Root Slide

The root snapshot (main content area) uses a two-phase staggered slide: the old page exits upward in 0.18s, then the new page enters from below after a 0.12s delay. The offset between exit and entry creates a brief overlap that feels fluid without being jarring.

Timeline (total ≈ 0.40s)

old page
0 → 0.18s · ease-in
new page
0.12s delay → 0.40s · ease-out
0s 0.12s 0.18s 0.40s
Keyframe Duration Easing Transform Delay
vt-slide-out (root) 0.18s ease-in translateY(0 → -40px) —
vt-slide-in (root) 0.28s ease-out translateY(40px) scale(0.98) → normal 0.12s 
@keyframes vt-slide-out {
  from { opacity: 1; transform: translateY(0);     }
  to   { opacity: 0; transform: translateY(-40px); }
}

@keyframes vt-slide-in {
  from { opacity: 0; transform: translateY(40px) scale(0.98); }
  to   { opacity: 1; transform: translateY(0)    scale(1);    }
}

::view-transition-old(root) {
  animation-name:            vt-slide-out;
  animation-duration:        0.18s;
  animation-timing-function: ease-in;
  animation-fill-mode:       both;
}

::view-transition-new(root) {
  animation-name:            vt-slide-in;
  animation-duration:        0.28s;
  animation-timing-function: ease-out;
  animation-fill-mode:       both;
  animation-delay:           0.12s; /* let old finish before new enters */
}

Adding New Named Regions

Assign a unique view-transition-name to any element that should animate independently of the root. If the element exists on both pages (e.g. a persistent header card), the browser treats it as a morphing surface. If it only exists on one page, it fades in or out automatically.

Persistent element (both pages)

Browser morphs the snapshot from old position to new position — creates a "shared element" effect.

.page-header-card {
  view-transition-name: vt-page-header;
}

Unique element (one page only)

Browser uses its default crossfade unless you supply ::view-transition-old/new keyframes.

.promo-banner {
  view-transition-name: vt-promo;
}
/* then optionally: */
::view-transition-new(vt-promo) {
  animation: vt-slide-in 0.28s ease-out both;
}

Names must be unique per document. The browser throws if two elements on the same page share a view-transition-name. For list items use a dynamic name (e.g. vt-holding-<id>). Also avoid giving view-transition-name to elements inside overflow: hidden containers — Chrome will silently clip their animation.

/* Give any element a unique name — no JS required */
.my-element {
  view-transition-name: vt-my-element; /* prefix with vt- by convention */
}

/* Optionally supply your own keyframes */
::view-transition-old(vt-my-element) { animation: vt-slide-out 0.18s ease-in both; }
::view-transition-new(vt-my-element) { animation: vt-slide-in  0.28s ease-out both 0.12s; }

/* Or suppress animation entirely (freeze it like topbar/sidebar) */
::view-transition-old(vt-my-element),
::view-transition-new(vt-my-element) { animation: none; }

Browser Support

The View Transition API for cross-document navigation is available in Chromium-based browsers from mid-2024 onward. Unsupported browsers fall back silently to a normal page load — the feature is a progressive enhancement and never breaks navigation.

Browser Status Since Notes
Chrome Supported v126 Full cross-document support
Edge Supported v126 Chromium-based — same support as Chrome
Firefox No-op — Normal navigation, no animation
Safari No-op — Normal navigation, no animation 
/* Respect reduced-motion — always included in transitions.css */
@media (prefers-reduced-motion: reduce) {
  ::view-transition-old(root),
  ::view-transition-new(root) {
    animation: none;
  }
}
