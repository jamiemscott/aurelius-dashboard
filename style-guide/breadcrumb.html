Style Guide

Breadcrumb

A lightweight horizontal path indicator that tells users where they are in the page hierarchy. Built to the WAI-ARIA APG breadcrumb pattern and defined in modules/breadcrumb.css. Typically sits above the page title in the .page-header region or at the top of a wizard/multi-step flow. Renders at 12px — smaller than body copy — so it adds context without competing with the page heading.

Anatomy

A <nav> landmark labelled "Breadcrumb" holds an ordered list (.breadcrumb-list), one .breadcrumb-item per level. The trail starts with the client's name, which links home, then each ancestor, then the current page. Every level is a link (.breadcrumb-link). The last one is the current page, marked with aria-current="page", which also gives it its brighter colour. CSS draws the slashes on each item after the first, so there is no text for a screen reader to read.

  2. My Investments
  3. Add Investment

Usage with Page Header

Place the breadcrumb inside the left column of .page-header, immediately above the .page-title. The 4px bottom margin on .breadcrumb provides the correct gap to the heading. Every page in the prototype uses this exact markup.

Building it in OutSystems

An ODC Container renders a <div>, so the roles go in its Attributes: navigation for the landmark, and list and listitem for the trail. Screen readers then announce the same landmark and list as the prototype's <nav> and <ol>. The classes style them the same way, because none of them depend on the element.

Inside the screen's page header, above the title:

  1. Add a Container. Set Style Classes to breadcrumb. In Attributes, add role = "navigation" and aria-label = "Breadcrumb".
  2. Inside it, add a Container with Style Classes breadcrumb-list and the Attribute role = "list".
  3. For each level, add a Container with Style Classes breadcrumb-item and the Attribute role = "listitem". Put a Link in it with Style Classes breadcrumb-link that goes to that level's screen. The first level is the client's name, and it goes to the home screen.
  4. On the last level's Link, which goes to the current screen, add the Attribute aria-current = "page".
  5. Don't add separators. .breadcrumb-item draws them.

Put this in a block with the levels as inputs if more than one screen needs it. The OutSystems UI Breadcrumbs pattern is themed too (.breadcrumbs-item in osui-theme/widgets/navigation.css), but it has no landmark or list and uses an icon separator, so it won't match the prototype or the APG pattern. Build the Container version above instead.

Do & Don't

Do

Use a labelled <nav> and an ordered list, make every level a link, and mark the last one with aria-current="page". Let CSS draw the separators.

Don't

Don't leave out the landmark or the list, and don't type the separators as text. Screen readers read each "/" aloud.

Accessibility Notes

This follows the APG breadcrumb example. <nav aria-label="Breadcrumb"> makes it a navigation landmark called "Breadcrumb", distinct from the main navigation. The <ol> tells screen reader users how many levels there are and where each one sits. Every level is a link, and aria-current="page" on the last one announces it as the current page. The separators are a CSS border with no text, so they are never announced. A forced-colours rule keeps them visible in Windows High Contrast. There is no keyboard interaction beyond tabbing through the links. WCAG 2.4.8 (Location) — Level AAA.
