Style Guide

Plan My Future

The scripted planning chat at /chat/plan-my-future. The chat reuses adv-* from modules/adviser.css; the plan panel lives in modules/plan.css and its Highcharts 13 styling in modules/plan-chart.css. All new classes are prefixed plan-.

Layout & drawer

.plan-layout is a centred two-column grid, at most 1560px wide: the chat (.chat-wrap.plan-chat) takes a third and the plan (aside.plan-panel[popover]) two thirds. The chat is sticky, and its message log is the only inner scroll area. The plan never scrolls on its own: it grows with its content and the page scrolls, which avoids nested scrollbars. Once the panel is 720px or wider, .plan-panel-body uses a container query for a 2fr / 1fr grid: the period pills and KPIs run across the top, the chart/table flip card takes two thirds with the allocation doughnut in the last third, and holdings, changes and assumptions run full width below. Holdings rows flow into as many 320px columns as fit. Above 1080px, author CSS overrides the browser’s [popover] hiding so the panel sits inline. Below 1080px it is hidden until the View plan button (popovertarget) opens it as a right-hand drawer. Focus handling, Escape to close and the backdrop come from the browser, with no script.

Period pills

These look like .range-pill but are real radio buttons inside a fieldset, so arrow keys and screen-reader grouping work with no script. The periods extend the site’s 1M · 3M · 6M · 1Y forward to 3Y, 5Y and All (25 years, the plan left to grow). Targets are at least 24px tall.

Chart ⇄ table flip card

The projection and the allocation each show as a chart or a table on the two faces of one card. A Chart/Table radio pair (styled like the period pills) inside a .plan-flippable section turns its .plan-flip-inner over with :has() and a 3D rotate, with no script. Both faces share one grid cell, so the card keeps the height of the taller face and nothing below it jumps. Each face’s visibility swaps at the half-turn, so the hidden face can’t take focus or be read. Reduced motion swaps the faces instantly; forced-colours mode gives each face a system border.

Holdings rows & badges

.plan-line rows show each holding’s status with data-status (kept, added or removed). Each row has a unique view-transition-name, so adding or removing a holding animates through the View Transitions API (turned off with reduced motion). The remove and undo buttons work without the chat. Their accessible names include the holding’s name.

Highcharts token bridge

Charts use Highcharts 13.0.0, the version OutSystems Charts (ODC) 3.12 ships, in styledMode. Highcharts outputs only class names. .plan-chart maps our tokens onto its --highcharts-color-N and --highcharts-neutral-color-* variables. It also resets Highcharts’ own color-scheme: light dark to inherit, so charts follow the site toggle rather than the OS. Each series colour reaches at least 3:1 against the card surface. Forced-colours mode switches to system colours.

Accessibility

How the page handles screen readers, keyboards and display settings.

  • The conversation is a role="log". Only finished replies are added to it, and the typing indicator is aria-hidden.
  • Each change to the plan is announced once in a separate polite status region, outside the drawer so it’s heard even when the drawer is closed.
  • The Highcharts accessibility module gives the charts keyboard navigation and screen-reader descriptions. Both the projection and allocation cards turn over to a table with their Chart/Table radios. Only the face showing is visible to keyboards and screen readers.
  • Chips and buttons that held focus are replaced after each reply, so focus moves to the newest chip, or the message box if there isn’t one.
  • Reduced motion removes the typing delay and turns off message, row, drawer and disclosure animations, and chart animation.
