Style Guide

Onboarding

The "Know Your Element" investment personality assessment is a bespoke full-screen experience at /onboarding. It uses the Five Elements motif (Water, Wood, Fire, Earth, Metal) to help users discover their investment style through a series of interactive screens. CSS lives in modules/onboarding.css; JS is split into screen-specific modules under src/js/onboarding/.

Architecture Overview

The onboarding experience is a single-page, multi-screen flow. Each screen is a <section> element with the hidden attribute; the active screen has hidden removed by the JS state machine. Screen transitions use CSS animation classes driven by data-state attributes. No routing library — pure vanilla JS.

JavaScript Modules

Each interactive screen has its own ES module to keep concerns isolated. The orchestrator (onboarding.js) manages the shared state object S, handles screen transitions, and collects answers. Screen modules are imported lazily or statically depending on complexity. Results are communicated via a custom event.

src/js/onboarding.js State machine — S object, goTo(), completeStep(), event dispatch
onboarding/dial.js SVG rotary dial — drag (mouse+touch), keyboard (ArrowLeft/Right)
onboarding/risk.js Custom visual range thumb synced to native <input type="range">
onboarding/swipe.js Card swipe — drag, keyboard (Arrow keys), accessible buttons
onboarding/rank.js Drag-to-rank — HTML5 drag API + keyboard (Space/Arrow/Enter/Esc)
onboarding/knowledge.js Tap-to-cycle confidence cards with dynamic aria-label updates
onboarding/amount.js Native range + bidirectional chip sync; chips use aria-pressed
onboarding/results.js Listens for ob:complete — calculates scores, animates el-bar fills 
// onboarding.js — state object shape
const S = {
  screen: 'welcome',   // current screen id
  risk: 50,            // dial position (0–100)
  riskSlider: 5,       // spectrum position (1–10)
  swipeAnswers: [],    // array of { card, direction }
  rank: [],            // ordered priority ids
  knowledge: {},       // { assetId: confidence (0|1|2) }
  amount: 5000,        // investment amount in £
};

// Completing a step and moving forward:
completeStep('dial', { risk: 72 });  // merges into S, calls goTo()

// Results received via custom event:
document.addEventListener('ob:complete', e => {
  // e.detail === final S object
});

Accessibility Approach

The onboarding experience replaces gesture-only interactions with fully keyboard and screen reader-operable alternatives. The following patterns are applied throughout.

Dial — #ob-dial

Mouse/touch drag rotates the dial. Keyboard: ArrowLeft/ArrowRight adjusts by 1; Shift+Arrow by 10. Uses role="slider" with aria-valuenow, aria-valuemin, aria-valuemax, and aria-valuetext (e.g. "72 — Balanced").

Card Swipe — #ob-swipe

Drag left/right to swipe. Keyboard: ArrowLeft = decline, ArrowRight = accept. Accessible labelled buttons appear below the stack for pointer users. An aria-live="polite" region announces each new card.

Rank & Sort — #ob-rank

HTML5 drag API for mouse users. Full keyboard: Space to grab, ArrowUp/ArrowDown to reorder, Enter/Space to drop, Escape to cancel. Position announced via aria-live on each move.

Knowledge Cards — #ob-knowledge

Cards cycle through confidence states (None → Basic → Experienced) on click. Each is a <button> with a dynamic aria-label updated on each state change to announce the new level.

Animations

All animations are wrapped in @media (prefers-reduced-motion: no-preference). When reduced motion is preferred, screens fade-in only — no sliding, rotation, or scale transforms.

/* Wrap all non-trivial animations */
@media (prefers-reduced-motion: no-preference) {
  .ob-screen[data-state="entering"] {
    animation: ob-screen-in 0.35s ease both;
  }
  .ob-screen[data-state="exiting"] {
    animation: ob-screen-out 0.25s ease both;
  }
}

/* Fallback: always apply the final state immediately */
.ob-screen {
  opacity: 1; /* visible when not hidden */
}
