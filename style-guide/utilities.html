Style Guide

Utilities

Small, single-purpose classes that replace style="…". Apply them to a component or an OSUI widget to adjust it without new CSS. Each one reads a design token, so it follows the theme in light and dark. They live in src/styles/modules/utilities.css.

When to use which

Reach for the most specific thing that already exists.

You needUse
A pattern with a name: card, button, drawerThe component class from its page in this guide.
A small adjustment to a componentA utility, such as u-mb-l or u-w-full.
The same four or more utilities repeatedA new component class in the right partial. Repetition means the pattern has earned a name.
A value only known at runtimeA --dyn-* custom property and its class. See Runtime values below.
A value that is not on the scaleUse the nearest step. If the design truly needs it, change the component, not the page.

Applying them

Stack classes in the markup. They have no dependencies and order in the attribute does not matter.

Portfolio value £842,300 
<div class="u-flex u-items-center u-justify-between u-gap-base u-bg-input u-radius-item u-p-base">
  <span class="u-text-1 u-fs-body u-fw-medium">Portfolio value</span>
  <span class="u-text-gold u-font-serif u-fs-3xl u-tabular">£842,300</span>
</div>

On OSUI components

Every OSUI widget takes extra classes, so the same utilities work on Buttons, Containers, Cards and Inputs. Use Style Classes on a Container, and ExtendedClass on widgets and blocks that expose it. Keep the widget’s own classes and add utilities after them.

WidgetPropertyExample value
ContainerStyle Classes"card card-pad u-mb-l"
ButtonStyle Classes"btn btn-primary u-w-full"
InputStyle Classes"form-control u-w-full"
ExpressionStyle Classes"u-text-3 u-fs-sm"
Block with ExtendedClassExtendedClass"u-mt-base"

Why utilities use !important. OutSystems wraps bundle.css in @layer theme.theme at runtime and leaves its own _Basic_ stylesheet unlayered, so a normal declaration in a utility would lose to _Basic_. !important reverses the layer order and lets a utility win on any widget, as the inline style it replaces did. See OutSystems Integration. The rule applies to this layer only. Components keep to the usual rule: !important only where _Basic_ competes.

Runtime values

Some values only exist at runtime: a progress percentage, a series colour from data. Set a --dyn-* custom property and add the class that consumes it. The style attribute then carries data only, and the CSS stays in the bundle. These properties do not inherit, so a value on a parent cannot leak into a nested element.

<!-- HTML or a JS template -->
<div class="u-h-full u-w-dyn u-bg-dyn" style="--dyn-w:62%;--dyn-bg:var(--el-water)"></div>

<!-- JS update -->
bar.style.setProperty('--dyn-w', score + '%');

<!-- OutSystems: add a style attribute with an expression -->
"--dyn-w:" + Score + "%"

Showing and hiding

Use the native hidden attribute, and el.hidden = true from JS. The theme makes it win over a component’s own display, so nothing needs display:none. In OutSystems, prefer an If widget when the content should not render at all.
