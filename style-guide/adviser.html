Style Guide

Adviser Chat

A full-page AI-adviser chat interface built for the .shell--no-sidebar layout. All component classes live in modules/adviser.css; layout containers (.chat-main, .chat-wrap) are in layout/layout.css. All classes are prefixed adv- or chat- to avoid conflicts with the existing floating chat widget in modules/chat.css. The module also ships OutSystems compatibility fixes for injected wrappers and pseudo-element arrows.

Shell Layout — .chat-main & .chat-wrap

The chat page uses .shell--no-sidebar on the root shell div. Inside the main area, two classes control layout. .chat-main removes the default .main padding so the interface reaches the edges. .chat-wrap centres and constrains content to 760px on wide viewports while staying full-width on mobile. Both are in layout/layout.css.

Context Bar — .chat-context

A sticky bar at the top of the chat that lets the user set session-level parameters before asking questions. On mobile it stacks vertically; above 480px it flows into a row. Each field wraps a label and a <select> in a .chat-context-field flex column. The styled custom arrow is a background-image SVG; the native browser arrow is suppressed with appearance: none.

Avatars — .adv-avatar

Two variants distinguish the sender of each message. The bot avatar (.adv-avatar--bot) shows the Aurelius monogram on a gold-dim background, painted with the --brand-monogram mask just like the brand mark. The "A" in the markup is a no-CSS fallback, hidden with font-size: 0. The user avatar (.adv-avatar--user) shows initials in a neutral treatment. On consecutive messages from the same sender, the avatar is set to visibility: hidden to avoid visual clutter while preserving the column width.

Message Rows — .adv-msg

Each message is an .adv-msg flex row containing an avatar and a bubble column. DOM order is always [avatar][bubble] for both senders. .adv-msg--bot aligns the row to the left; .adv-msg--user pushes the row to the right with margin-left: auto — the avatar stays on the left of the bubble in both cases. Consecutive same-sender messages collapse their spacing from 12px to 4px.

Bubbles — .adv-bubble-inner

Bubble shape is controlled by border-radius — the "pinched" corner (4px) is always top-left, pointing toward the avatar on the left. Bot bubbles use --bg-card with a neutral border; user bubbles use --gold-dim with a gold glow border. Both use the same padding and the same border-radius: 4px 16px 16px 16px. Never apply colours to .adv-bubble-inner directly — colours are inherited from the .adv-msg--bot / .adv-msg--user parent selector.

Status Bubbles — .adv-bubble-inner--{variant}

Modifier classes for .adv-bubble-inner that convey system status within the chat flow — errors, confirmations, warnings, and informational notices. The four variants use the same --fb-color / --fb-bg / --fb-border custom property tokens as .feedback-message variants in modules/feedback.css, keeping the status palette consistent across the product. Apply the modifier alongside the base class: class="adv-bubble-inner adv-bubble-inner--error". Add role="alert" for error messages that need immediate screen-reader announcement.

Message Text & Rich Content — .adv-text

.adv-text is the prose wrapper inside a bubble. It supports paragraph stacking (each <p> has 8px bottom margin, cleared on the last child), <strong> for emphasis, and <code> for inline identifiers — ticker symbols, account numbers, function names. Never use <br> to separate thoughts; use separate <p> elements instead.

A

Your portfolio contains three primary positions: UK Equities, Global Bonds, and Alternatives.

The largest single holding is VWRL at 24% of total assets. Current yield is 2.1% — slightly below your 2.5% target.

I recommend reviewing the bond allocation ahead of the Q3 rebalancing window.

10:03

  <p class="adv-text">Third paragraph — no bottom margin on last child.</p>
</div>

Session Divider — .adv-divider

A horizontal rule that marks the start of a new conversation session or date group. The label is flanked by hairline rules built with CSS ::before / ::after pseudo-elements. Use role="separator" for accessibility. The label text is typically a date ("Today", "Yesterday", "12 April 2026").

Suggestion Chips — .adv-chip

Short-cut prompt buttons rendered below a bot message to guide the user towards common follow-up questions. They sit inside an .adv-suggestions flex-wrap container. Clicking a chip should populate the textarea with the chip's text — never submit automatically. Chips disappear or deactivate once the user has typed a custom message. Each chip must be a <button> for keyboard and AT access.

Typing Indicator — .adv-dots

A three-dot bounce animation shown inside a bot bubble while a response is being generated. The dots use @keyframes chat-bounce (defined in theme/animations.css) with staggered animation-delay values. Wrap the entire message row in aria-label="Aurelius is typing" and set aria-hidden="true" on the dots themselves — the row's label provides the accessible announcement. Input Bar — .adv-input-bar

A sticky footer bar housing the auto-resizing textarea and circular send button. The bar is a flex row with align-items: flex-end so both elements bottom-align as the textarea grows. The send button (.adv-send-btn) should be disabled when the textarea is empty and enabled on first keystroke. The textarea auto-resizes in JavaScript — see chat/index.html for the implementation. Maximum height is capped at 140px before scrolling.

Empty State — .chat-empty

Displayed when there are no messages yet — replaces the .adv-messages content. Centred vertically and horizontally using flex. The orb echoes the brand mark with the gold-dim palette. Below the heading and subtext, a 2-column starter grid (.chat-starter-grid) provides clickable prompt tiles that populate the textarea when clicked. Hide the empty state and show the messages list as soon as the first message is sent.

Scroll to Bottom — .chat-scroll-btn

A floating circular button that appears when the user has scrolled up and there are newer messages below. It is absolutely positioned within the .chat-wrap container (which must have position: relative). The button starts at opacity: 0; pointer-events: none and transitions to visible via the .is-visible state class, toggled by a scroll event listener in JavaScript.

Scroll position indicator area

<!-- Inside .chat-wrap (position: relative) -->
<button class="chat-scroll-btn" aria-label="Scroll to latest message">
  <svg aria-hidden="true" focusable="false" width="16" height="16"
       fill="none" stroke="currentColor" stroke-width="2" viewBox="0 0 24 24">
    <polyline points="6 9 12 15 18 9"/>
  </svg>
</button>

<!-- JS: toggle .is-visible based on scroll position -->
<script>
  const btn = document.querySelector('.chat-scroll-btn');
  const msgs = document.querySelector('.adv-messages');
  msgs.addEventListener('scroll', () => {
    const atBottom = msgs.scrollHeight - msgs.scrollTop - msgs.clientHeight < 80;
    btn.classList.toggle('is-visible', !atBottom);
  });
</script>

OutSystems Compatibility

When the chat module is rendered in OutSystems, the platform injects wrapper elements and pseudo-elements that can disrupt flex layout and introduce duplicate UI chrome. Three targeted overrides in modules/adviser.css neutralise these without affecting the static HTML demo. All rules are scoped tightly to avoid bleeding into other page components.

Fix 1 — Textarea span wrapper

OutSystems wraps the <textarea> in an auto-generated <span> that cannot be removed. This makes the span the flex child instead of the textarea, collapsing the input to its intrinsic width. display: contents makes the span invisible to the flex algorithm so the textarea participates directly.

/* OS injects: <span><textarea></textarea></span> */
.adv-input-bar > span {
  display: contents; /* span vanishes from box model; textarea becomes direct flex child */
}

Fix 2 — Dropdown container arrow

OS wraps <select> in a div.dropdown-container and renders its chevron via ::after using an icon font variable (content: var(--osui-icon-arrow-down)). This creates a second arrow alongside our background-image chevron. We suppress the pseudo-element and give the wrapper flex: 1 so the select inside it fills the column width.

/* OS injects: <div class="dropdown-container"><select>…</select></div> */
.chat-context-field .dropdown-container {
  flex: 1;
  min-width: 0;
  position: relative; /* preserve OS stacking context for transitions */
}

.chat-context-field .dropdown-container::after {
  content: none !important; /* remove icon-font arrow */
}

Fix 3 — Sibling icon fallbacks

Additional fallback selectors cover sibling icon elements that different OS widget versions may inject alongside the <select>. Scoped to .chat-context-field to avoid hiding elements elsewhere on the page.

.chat-context-field select ~ svg,
.chat-context-field select ~ i,
.chat-context-field select ~ span[class],
.chat-context-field [class*="arrow"],
.chat-context-field [class*="chevron"],
.chat-context-field [class*="caret"] {
  display: none !important;
}
